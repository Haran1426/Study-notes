# 실시간 화면 번역

<img src="assets/branding/launcher_icon.png" alt="실시간 화면 번역 앱 아이콘: A와 가 사이의 양방향 화살표" width="160">

Android 휴대폰에서 다른 앱을 사용하는 동안 화면 속 외국어를 인식하고, 번역문을 화면 위에 표시하는 앱을 목표로 한다. Flutter와 Dart를 직접 코딩하면서 공부하고, Android 전용 기능은 Kotlin으로 연결해 개인 포트폴리오와 향후 배포까지 이어가는 프로젝트다.

> **현재는 초기 개발 단계다.** 아이콘·시작 화면 설정과 홈 화면의 기본 틀을 작성했다. 실시간 화면 캡처, 문자 인식, 번역, 오버레이는 아직 구현하지 않았다.

기록 기준일: **2026-10-02**. 아래 진행 상태는 현재 작업 폴더 기준이며, 아직 커밋하지 않은 변경사항도 포함한다.

## 1. 왜 만드는가

외국어 게임, 앱, 웹페이지를 볼 때 문장을 복사하거나 스크린샷을 번역기에 가져가는 과정이 번거롭다. 글자를 복사할 수 없는 화면에서는 특히 불편하다.

예를 들어 게임 화면에 `Start a new game`이 보이면, 사용자가 앱을 오가지 않아도 같은 화면 아래에 `새 게임 시작`이라는 번역 결과를 보여주는 것이 목표다.

### 프로젝트 목표

- 사용자가 보고 있는 화면의 외국어를 한국어로 이해하도록 돕는다.
- Flutter 화면 구성과 상태 변경, 비동기 처리를 실제 기능 안에서 배운다.
- Flutter와 Kotlin 연결, Android 권한과 서비스 동작을 단계적으로 익힌다.
- 선택한 기술과 문제 해결 과정을 설명할 수 있는 포트폴리오를 만든다.
- 실제 기기 테스트와 안정화를 거쳐 Android 배포를 준비한다.

## 2. 계획한 사용자 흐름

```text
앱 실행
→ 흰색 배경의 로고 시작 화면
→ 홈 화면에서 원본 언어와 번역 언어 선택
→ 사용자가 '번역 시작' 누름
→ 필요한 권한의 목적 안내 및 승인
→ 다른 앱으로 이동
→ 화면 캡처
→ OCR로 문자 인식
→ 인식한 문장 번역
→ 화면 하단의 번역 패널에 표시
→ 일시정지 또는 종료
```

OCR(광학 문자 인식)은 이미지 속 글자를 문자열로 추출하는 기술이다. 오버레이는 다른 앱 위에 겹쳐 표시되는 창이다.

권한 요청은 번역 시작 동작에 연결할 계획이다. 앱을 처음 켠 사용자는 먼저 홈 화면을 보고 기능을 선택할 수 있게 한다. 실제 권한 요청과 화면 캡처 동작은 아직 없다.

### 홈 화면 구상

```text
실시간 화면 번역

원본 언어  [영어 ▼]
번역 언어  [한국어 ▼]

[번역 시작]

상태: 대기 중
```

처음에는 영어→한국어만 실제 지원한다. 언어 선택 UI를 연습하더라도 지원하지 않는 번역 기능이 작동하는 것처럼 표시하지 않는다. 설정 화면과 패널 꾸미기는 기본 동작을 완성한 다음 추가한다.

## 3. 첫 번째 완성 버전의 범위

MVP(최소 기능 제품)는 핵심 흐름을 실제로 사용할 수 있는 첫 버전이다.

### 포함할 기능

- Android에서 영어→한국어 번역
- 화면 캡처와 다른 앱 위 표시 권한 안내
- 번역 시작, 일시정지, 종료
- 화면 이미지를 OCR로 분석
- 기기 내 번역 모델로 문장 번역
- 화면 하단의 반투명 번역 패널
- 약 1초 간격의 화면 분석을 출발점으로 성능 조정
- 처리 중 새 프레임을 쌓지 않는 제한
- 같은 원문을 반복 번역하지 않는 비교·캐시
- 권한 거절, 글자 없음, 모델 다운로드 실패 안내
- 캡처 중임을 알리는 지속 알림과 종료 수단

### 이후로 미룬 기능

- iOS 지원
- 원문 위치마다 번역문을 정확히 덮어쓰기
- 모든 언어 자동 감지 및 다국어 지원
- 로그인, 서버, 번역 기록 동기화
- 높은 프레임 속도로 매 화면 분석
- 복잡한 애니메이션과 디자인 시스템

원문 위치에 덮어쓰는 방식은 글자 좌표, 회전, 캡처 크기와 화면 크기의 차이를 함께 처리해야 한다. 따라서 먼저 하단 패널로 번역 흐름을 완성한다. 1초는 분석 요청 간격의 초기 목표이며, 번역이 1초 이내에 끝난다는 보장은 아니다.

## 5. 기술 구성과 선택 이유

다음 표에서 **계획**으로 표시한 기술은 아직 기능에 연결하지 않았다.

| 역할 | 기술 | 상태 및 선택 이유 |
|---|---|---|
| 앱 화면 | Flutter / Dart | 사용 중. 위젯 배치와 화면 상태를 직접 학습 |
| Android 기기 기능 | Kotlin | 기본 `MainActivity` 존재. 캡처·오버레이 기능 구현은 계획 |
| Flutter↔Android 연결 | MethodChannel | 계획. Dart에서 Android 기능 호출 및 결과 전달 |
| 화면 캡처 | MediaProjection | 계획. Android의 화면 공유·캡처 기능 사용 |
| 문자 인식 | ML Kit Text Recognition | 계획. 화면 이미지에서 원문과 글자 영역 추출 |
| 번역 | ML Kit Translation | 계획. 기기 내 번역으로 시작 |
| 지속 실행 | Foreground Service | 계획. 실행 중임을 알리는 알림과 작업 관리 |
| 화면 위 표시 | Android 오버레이 | 계획. 다른 앱 위에 번역 패널 표시 |
| 아이콘 생성 | flutter_launcher_icons `^0.14.4` | 개발 의존성. 일반·적응형 아이콘 생성 |
| 시작 화면 생성 | flutter_native_splash `^2.4.8` | 개발 의존성. Android 버전별 시작 리소스 생성 |

### 계획한 처리 구조

```text
Flutter UI: 언어 선택 / 시작·중지 / 상태 표시
    ↓ MethodChannel
Kotlin: 권한 결과 처리 및 캡처 서비스 제어
    ↓
화면 이미지 → OCR → 이전 원문과 비교 → 번역 → 오버레이 갱신
```

Flutter는 UI를 담당하고 Kotlin은 Android 운영체제 기능을 담당한다. OCR과 번역을 Kotlin 서비스에서 수행하는 것을 목표로 하되, 첫 이미지 실습에서 사용한 Flutter 래퍼가 있다면 단계적으로 이전한다.

초기 상태 관리는 `setState`로 배운다. 여러 화면이 상태를 공유하면서 필요성이 확인되면 상태 관리 도구를 검토한다.

## 6. 공부하면서 만드는 순서

강의 수강을 전제로 하지 않는다. 작은 기능을 직접 작성하고, 그 기능에 필요한 문법과 원리를 확인하며 진행한다. 자세한 일정은 [학습·개발 계획서](docs/learning-plan.md)를 참고한다. 계획서의 8주는 주당 약 15시간을 가정한 참고 일정이며, 이해도와 실제 가능한 시간에 맞춰 늘릴 수 있다.

| 단계 | 직접 만들 결과 | 배울 내용 | 완료 기준 |
|---|---|---|---|
| 1. 홈 화면 | 언어 표시, 시작 버튼, 상태 문구 | 위젯 배치, 이벤트, `setState` | 버튼을 누르면 상태가 바뀜 |
| 2. 가짜 번역 | 잠시 로딩 후 예시 결과 | 클래스, `Future`, `async/await`, 예외 처리 | 로딩·성공·실패를 구분해 표시 |
| 3. 이미지 OCR | 스크린샷에서 원문 추출 | 이미지 선택, 패키지 사용, OCR 구조 | 이미지 속 영어가 화면에 출력됨 |
| 4. 이미지 번역 | 원문과 한국어 번역문 | 모델 다운로드, 비동기 작업 연결 | 이미지 한 장의 인식→번역 완료 |
| 5. Kotlin 연결 | Flutter 버튼으로 네이티브 호출 | Kotlin 기초, MethodChannel | 성공값과 오류를 Flutter에서 처리 |
| 6. 화면 한 장 캡처 | 다른 앱 화면에서 원문 추출 | 권한, MediaProjection, 서비스 | 승인·거절·종료 흐름 처리 |
| 7. 실시간 패널 | 다른 앱 위 번역문 갱신 | 반복 작업, 중복 제한, 오버레이 | 실행·일시정지·종료가 안정적으로 동작 |
| 8. 안정화·배포 | 설치 가능한 앱과 시연 자료 | 테스트, 성능 관찰, 배포 준비 | 실제 기기 검증과 제한 사항 기록 |

각 기능은 다음 과정을 반복한다.

```text
작은 코드 작성 → 실행 → 코드 일부 변경 → 원리 확인
→ 앱에 적용 → 실패 상황 확인 → 커밋 → 학습 기록
```

### 2026-10-02 — 앱 아이콘과 시작 화면

- `A ↔ 가` 심볼이 있는 투명 PNG를 원본 로고로 사용했다.
- 로고 비율을 유지하며 일반 아이콘, 적응형 전경, Android 버전별 시작 이미지를 생성했다.
- 원형으로 잘리는 영역을 고려해 아이콘과 시작 이미지에 각각 여백을 넣었다.
- 거의 투명한 픽셀 때문에 중심이 어긋나는 문제를 발견해, 보이는 심볼 경계를 기준으로 배치를 보정했다.
- 밝은·어두운 모드의 시작 화면을 모두 흰색으로 설정했다.
- 로고를 보여주기 위한 강제 대기 시간은 넣지 않았다.
- 재생성 명령과 적용 결과를 [브랜딩 문서](docs/branding.md)에 기록했다.

### 2026-10-02 — 홈 화면 코드 분리와 기본 구조 학습

- `lib/Screen/mainMenu.dart`에 `Mainmenu` 화면을 분리했다.
- `import`로 다른 파일의 클래스를 가져오는 방법을 학습했다.
- 생성자에서 `required this.title`로 제목을 전달받고 `final String title`에 저장했다.
- `createState()`로 `Mainmenu`와 `_MainmenuState`를 연결했다.
- `build()`가 화면에 표시할 위젯 구성을 반환한다는 점을 학습했다.
- `Scaffold`와 `AppBar`로 기본 화면을 구성하고 `widget.title`로 전달받은 제목을 읽었다.

```text
main.dart에서 Mainmenu(title: ...) 생성
→ Mainmenu 생성자가 제목을 저장
→ createState()가 _MainmenuState 생성
→ build()에서 Scaffold와 AppBar 구성
→ Text(widget.title)로 제목 표시
```

이후 작업도 날짜, 구현 결과, 배운 원리, 막힌 점, 확인 방법을 함께 기록한다. 긴 문제 해결 기록은 필요할 때 `docs/dev-log/`에 추가하고 README에서 연결한다.

- [ ] 실제 휴대폰에서 아이콘과 완전 종료 후 시작 화면 확인

첫 완료 목표는 **시작 버튼을 누르면 상태 문구가 바뀌는 홈 화면**이다. 이 단계에서는 화면 캡처나 실제 번역은 수행하지 않는다.

## 9. 현재 파일 구조

```text
lib/
├─ main.dart                    # 앱 실행, 테마, 첫 화면 연결
└─ Screen/
   └─ mainMenu.dart             # Mainmenu와 상태 객체, 홈 화면 기본 틀

assets/branding/                # 원본 로고와 파생 이미지
android/app/src/main/           # Android 이름, 아이콘, 시작 화면 설정
docs/
├─ learning-plan.md             # 상세 학습·개발 계획
└─ branding.md                  # 아이콘·시작 화면 재생성과 검증
tool/
└─ prepare_branding.ps1         # Windows용 파생 이미지 생성
flutter_launcher_icons.yaml     # 아이콘 생성 설정
flutter_native_splash.yaml      # 시작 화면 생성 설정
```

위 구조는 현재 실제 파일 기준이다. 서비스·모델·설정 화면은 해당 기능을 만드는 시점에 추가한다. Dart 파일의 `snake_case` 이름 규칙에 맞춘 폴더·파일 이름 정리도 추후 진행한다.

## 10. 실행 방법

검증에 사용한 환경은 Windows, Flutter 3.47.2, Dart 3.13.2다. 프로젝트의 Dart SDK 조건은 `^3.13.2`이며, 실행에는 Flutter SDK, Android SDK와 실제 기기 또는 에뮬레이터가 필요하다.

처음 내려받는 경우:

```powershell
git clone https://github.com/Haran1426/Live-screen-translation.git
cd Live-screen-translation
flutter pub get
flutter devices
flutter run -d <Android기기ID>
```

`<Android기기ID>`는 `flutter devices` 결과의 실제 ID로 바꾼다. Android 기기가 하나만 선택 가능한 환경에서는 `flutter run`으로 실행해도 된다.

로고 파생 이미지와 Android 리소스를 다시 생성할 때:

```powershell
.\tool\prepare_branding.ps1
dart run flutter_launcher_icons
dart run flutter_native_splash:create
```

아이콘과 네이티브 시작 화면 변경은 Hot Reload만으로 반영되지 않는다. 앱을 다시 빌드·설치하고, 완전히 종료한 뒤 홈 화면 아이콘으로 시작한다. 자세한 설명은 [브랜딩 문서](docs/branding.md)에 있다.

## 11. 검증 상태와 앞으로의 테스트

### 확인한 내용

아이콘·시작 화면 적용 직후, 홈 화면 분리 **이전 코드**에서 다음을 확인했다.

- `flutter analyze --no-pub`: 문제 없음
- `flutter test --no-pub`: 당시 기본 카운터 테스트 통과
- `flutter build apk --debug --no-pub`: Android APK 빌드 성공
- APK의 앱 이름과 기존 패키지 식별자 유지 확인
- 적응형 아이콘과 Android 12 시작 이미지의 원형 안전 영역 밖 유색 픽셀 0개 확인

이후 홈 화면을 별도 클래스로 변경했으므로, 위 결과가 현재 코드 전체의 테스트 통과를 의미하지는 않는다. `test/widget_test.dart`는 아직 삭제된 카운터 동작을 검사하므로 현재 홈 화면에 맞게 수정해야 한다. 홈 화면 변경 후 분석·테스트·빌드 재검증과 실제 기기 화면 확인은 남아 있다.

검증 명령:

```powershell
flutter analyze
flutter test
flutter build apk --debug
```

### 기능 구현 후 확인할 상황

- 권한 승인, 거절, 재요청과 캡처 도중 종료
- 버튼을 빠르게 여러 번 누르는 경우
- 글자가 없는 화면, 긴 문장, 작은 글자
- 모델 다운로드 실패와 다운로드 이후 오프라인 사용
- 같은 화면 반복, 화면 스크롤, 회전
- 다른 앱으로 이동하거나 돌아오는 경우
- 번역 패널이 캡처되어 재번역되는 현상 방지
- 화면이 바뀐 뒤 이전 번역 결과가 늦게 덮어쓰는 현상 방지
- 중지 후 캡처·OCR·오버레이·알림 자원 정리
- 장시간 실행 시 처리 시간, 발열, 배터리 관찰

## 12. 개인정보 처리와 개발 시 주의할 점

다음은 기능 구현 시 지킬 **설계 목표**다. 아직 화면 캡처 기능은 없다.

- 사용자 동의 후 화면 캡처를 시작한다.
- 캡처 이미지의 영구 저장과 서버 전송을 기본 기능에 포함하지 않는다.
- OCR과 번역은 가능한 기기 내부에서 처리한다.
- 캡처 중임을 알리고 즉시 종료할 수 있게 한다.
- 개발 로그에 화면 원문과 민감한 정보를 남기지 않는다.
- 캡처가 제한된 화면의 보호를 우회하지 않는다.
- 배포 전 실제 수집·처리 동작을 기준으로 개인정보 안내와 스토어 정책을 확인한다.

## 13. 포트폴리오와 배포 준비

앱이 실제로 동작하면 다음 자료를 추가한다.

- 홈 화면과 번역 패널 스크린샷
- 다른 앱에서 번역이 동작하는 짧은 시연 영상
- Flutter와 Kotlin 역할 및 전체 데이터 흐름
- 기술 선택 이유와 구현 과정에서 해결한 문제
- 중복 요청 제한 전후의 처리 횟수·시간 비교
- 테스트 기기와 Android 버전, 알려진 제한 사항
- 설치 방법과 릴리스 기록

배포 전에는 릴리스 서명, 패키지 식별자, 버전 관리, 개인정보 안내, Google Play 요구사항을 확인한다. 현재는 디버그 빌드 검증 단계이며 스토어 배포나 정식 릴리스는 하지 않았다.
